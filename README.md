# Análise de Chamados de TI (Helpdesk) 🎫

> 🇬🇧 [English version below](#it-helpdesk-ticket-analysis-)

Projeto de portfólio que simula a rotina de um suporte/helpdesk de TI: geração de
1.500 chamados **100% sintéticos**, consultas SQL documentadas e gráficos
interativos para responder perguntas de negócio.

## Objetivo

Mostrar, na prática, que eu entendo a rotina de suporte de TI e sei escrever SQL
de verdade — como projeto de portfólio para conquistar minha primeira vaga de
Jovem Aprendiz em TI e, no futuro, evoluir para Analista de Dados.

## Perguntas de negócio (KPIs)

- Tempo médio de resolução por categoria
- % de chamados dentro do SLA (geral e por prioridade)
- Picos de abertura de chamados por dia da semana e hora
- Ranking de técnicos por % dentro do SLA

## Ferramentas

- Python, Pandas, NumPy — geração dos dados sintéticos
- SQLite — banco de dados (criado pelo próprio notebook, do zero)
- SQL — todas as consultas, documentadas em `sql/consultas.sql`
- Plotly — gráficos interativos dentro do notebook
- Looker Studio — só para gerar os prints do dashboard em `images/` (gratuito)
- Jupyter Notebook, publicado no Kaggle

Nenhuma ferramenta paga foi usada.

## Dados

Todos os dados são **sintéticos**, gerados por código (`src/gerar_dados.py`) com
seed fixa (`42`), para o resultado ser sempre o mesmo. Nenhum dado real de
pessoas ou empresas é usado. Campos: `id`, `categoria`, `prioridade`,
`data_abertura`, `data_fechamento`, `sla_horas`, `tecnico`, `status`.

## Como executar

1. Clone o repositório:
   ```bash
   git clone https://github.com/klaytonsi/chamados-ti-helpdesk.git
   cd chamados-ti-helpdesk
   ```
2. Instale as dependências:
   ```bash
   pip install -r requirements.txt
   ```
3. Abra `notebooks/01_chamados_ti.ipynb` e rode as células em ordem — o
   notebook gera os dados e o banco SQLite do zero. Funciona mesmo depois de
   reiniciar a sessão/ambiente.
4. (Opcional) Gere só o banco SQLite pela linha de comando:
   ```bash
   python src/gerar_dados.py
   ```

Também disponível pronto para rodar no Kaggle: *(link do notebook publicado)*.

## Aprendizados

- Praticar SQL com window functions (`RANK() OVER`) e CTEs em consultas que
  respondem perguntas de negócio reais de um helpdesk.
- Modelar dados sintéticos realistas (padrão semanal, distribuição log-normal
  de tempo de resolução) em vez de dados puramente aleatórios.
- Manter um projeto leve e 100% reproduzível, sem depender de arquivos
  grandes versionados nem de nenhuma ferramenta paga.

# IT Helpdesk Ticket Analysis 🎫

Portfolio project that simulates an IT helpdesk routine: generating 1,500
**fully synthetic** tickets, documented SQL queries, and interactive charts to
answer real business questions.

## Goal

Show, in practice, that I understand the IT support routine and can write
real SQL — as a portfolio project to land my first Junior IT Apprentice role
and, later, grow into a Data Analyst.

## Business questions (KPIs)

- Average resolution time by category
- % of tickets within SLA (overall and by priority)
- Ticket opening peaks by weekday and hour
- Technician ranking by % within SLA

## Tools

- Python, Pandas, NumPy — synthetic data generation
- SQLite — database (created by the notebook itself, from scratch)
- SQL — all queries, documented in `sql/consultas.sql`
- Plotly — interactive charts inside the notebook
- Looker Studio — only to generate the dashboard screenshots in `images/` (free)
- Jupyter Notebook, published on Kaggle

No paid tool was used.

## Data

All data is **synthetic**, generated by code (`src/gerar_dados.py`) with a
fixed seed (`42`), so the result is always the same. No real data about
people or companies is used. Fields: `id`, `categoria`, `prioridade`,
`data_abertura`, `data_fechamento`, `sla_horas`, `tecnico`, `status`.

## How to run

1. Clone the repository:
   ```bash
   git clone https://github.com/klaytonsi/chamados-ti-helpdesk.git
   cd chamados-ti-helpdesk
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Open `notebooks/01_chamados_ti.ipynb` and run the cells in order — the
   notebook generates the data and the SQLite database from scratch. It works
   even after restarting the session/environment.
4. (Optional) Generate only the SQLite database from the command line:
   ```bash
   python src/gerar_dados.py
   ```

Also available ready to run on Kaggle: *(published notebook link)*.

## Results (seed 42)

| KPI | Result |
|---|---|
| Slowest category | Hardware (~28.9 h average) |
| Fastest category | Acesso / Senha (~3.3 h average) |
| Overall % within SLA | 85.0% |
| Weakest SLA tier | Critical (63.0%) |

| Best technician (SLA) | Técnico 01 (90.2%) |

## Learnings

- Practicing SQL with window functions (`RANK() OVER`) and CTEs on queries
  that answer real helpdesk business questions.
- Modeling realistic synthetic data (weekly pattern, log-normal resolution
  time) instead of purely random data.
- Keeping a project light and fully reproducible, with no large files
  committed and no paid tools.

## Security and privacy

No real personal data at all (LGPD does not apply: everything is synthetic)
and no secrets in the code — see `.env.example`.
